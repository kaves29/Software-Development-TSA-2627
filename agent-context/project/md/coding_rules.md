# Coding rules

- Follow the self-documenting code principle: use descriptive variable and function names and clear structure.
- Keep code simple, concise, and production-ready. Follow established conventions for the language and existing codebase; refine specific conventions with the team as implementation begins.
- Treat comments as a signal to improve naming or structure. Never comment merely to explain what code does.
- Use comments only to explain why an unintuitive choice is necessary, such as an edge case or business rule.
- Do not leave TODOs, placeholders, or unfinished behavior in delivered code.
- Validate small changes iteratively with meaningful tests. Explain what was tested, results, and remaining limitations.
- Preserve readable code and useful documentation. The supplied TSA rubric includes commenting, structure, formatting, and readability; use necessary rationale comments and separate documentation rather than redundant comments.
